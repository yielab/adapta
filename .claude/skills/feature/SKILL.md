# Feature work in Adapta

## 0. Load only what you need

`CLAUDE.md` is already in context — **do not re-read it**. To find code, read
`.claude/context/repo-map.md` first; grep only when the map is silent, and scope the
grep to a directory. Read `specs/openapi.yaml` in slices (`grep -n` for the path, then
`sed -n`), never whole. If a question needs sweeping many files, dispatch one subagent
and keep only its conclusion.

## 1. Intake — read the task block, then only its Files (hard budget)

If it comes from `TODO.md`, that entry already carries Context / Scope / Steps / Files /
Contract impact / Gate / Acceptance / Close — read **that block only**:

```
grep -n '^### <id>' TODO.md          # e.g. '^### E1.3'
sed -n '<start>,<next-heading-1>p' TODO.md
```

Never read a whole section (`§E`, `§C`) or the status snapshot to pick up one task.
If the task doesn't exist in `TODO.md`, open it there first (see `docs-sync` → roadmap).

Then open **exactly the files the block's Files line names**, at the line anchors it
gives (`sed -n 'a,bp'`), before anything else. Opening a file the block does not name is
a scope signal: either the block is wrong (fix the block, one line) or you are widening
the task (stop — open a follow-up task instead). Budget for a normal task: the block +
its Files + one test file. No repo-wide grep; `repo-map.md` only if a Files line is
ambiguous.

State in one line before editing: *what changes · which contract fires · which gate ·
what "done" is observable as*. That line is the first line of your closure note (§5).

## 2. Contract first — always

| Trigger | Contract | Do this before touching handlers |
|---|---|---|
| Request/response shape, new route, new field | **API** — `specs/openapi.yaml` | edit spec → `make validate-spec` → `make generate` → routers consume the generated DTO (no hand-written models; `tests/test_generated_models_wired.py` enforces it) |
| New/changed table or column | **DB** — Alembic | `make migration MSG="…"` → review the autogenerated file → `make migrate` → `make migrate-test` |
| Dataset format, eval semantics | **Model** — `specs/schemas/training_dataset.schema.json` + eval gate | update the schema, then the validator in `adapta/services/training.py`, then the gate in `adapta/services/adapters.py` |

Nothing else is protected. Breaking changes to *implementation* are expected and
preferred over compatibility shims.

## 3. Implement to the house invariants

- **Errors:** raise a typed `DomainError` from `adapta/domain/errors.py`. Never
  `HTTPException(detail=str(e))` — `make check-leaks` is a CI gate. Put anything unsafe
  to show a client in `internal_detail` (logged, never serialized).
- **Never rewrite** `adapta/core/inference.py`, `adapta/core/model_manager.py`,
  `adapta/training/trainer.py` — wrap and call them.
- **Never hand-edit** `adapta/models/generated/models.py` — regenerate.
- **Commit before returning** in mutating handlers (deferred-commit race).
- Deps go in `pyproject.toml` only, then `make up` on the host. No manual `pip install`.
- Found a stub, mock, or dummy value? Delete or finish it — do not build around it.

## 4. Test at the right level

Add or extend the test that names the feature (see repo-map "Tests"). In-process tests
need no server/DB. Reach for `tests/integration/` or a GPU e2e only when the change
touches serving, training, or the eval gate.

## 5. Gate, document, close — and stop

Run **the gate the task block names** (it was chosen from `.claude/context/gates.md`
when the task was written); escalate one rung only if that gate cannot see your
change. Not `ci-full` by default.

Then close in this order, nothing more:

1. **docs-sync** — only the surfaces the block's Close line lists.
2. **Close in `TODO.md`:** heading gets `— ✅ DONE (YYYY-MM-DD)`, one **Done.** paragraph ≤ 8 lines
   (what changed, which gate ran and its result, anything skipped and why) and one **Handoff.**
   line; then move the whole block — Context/Steps intact — to `CHANGELOG.md` (top dated section)
   and flip its board row to `done`. The roadmap keeps only open blocks.
3. **ship** if the user asked for a commit; otherwise report and stop.

Do not continue into the next task, "while you're here" fixes, or refactors the block
did not ask for. Anything you noticed goes into one line under the task as
`- **Follow-up.** …` (or a new block if it is real work) — not into the diff.

## Definition of done

Contract updated first · invariants held · test proving the acceptance condition ·
the block's gate green · the block's Close surfaces true · closure note written ·
nothing outside the block's Files changed without a one-line reason in the note.
