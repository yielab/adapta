# CLAUDE.md — working agreement for agents

## What this project is

**Adapta is a self-hosted model-customization platform.** Teams deploy it on their own servers (data never
leaves their infrastructure) to specialize and serve private language models behind one OpenAI-compatible API:

- **Knowledge (RAG):** upload documents → Docling parsing + OCR → chunk → embed (sentence-transformers) → per-project ChromaDB →
  hybrid retrieval (vector + Postgres full-text, RRF, optional cross-encoder rerank) → cited answers. CPU-only.
- **Bring your own adapter (LoRA):** import a GGUF/PEFT adapter; the CPU worker converts, probe-loads and gates it
  against the base on the project's eval set (`passed`/`failed`), and only a passed adapter serves. Adapta verifies and serves adapters; it does not train them (removed 2026-10-10; [guide](docs/user-guide/bring-your-own-adapter.md));
  image *generation* is out, permanently.
- **Composed serving:** one endpoint can inject retrieved context *and* apply the adapter — facts from RAG,
  tone/format from the adapter.

Multi-user: registering creates an organization; teammates join by invite. A dev admin
(`admin@example.com` / `admin12345`) is seeded on an empty DB. The UI says *"give it knowledge"* (RAG) vs
*"change how it behaves"* (adapters) — never "training" for RAG.

Authoritative scope: [docs/reference/PRODUCT_DEFINITION.md](docs/reference/PRODUCT_DEFINITION.md). The code is
the real implementation — no mocks, no dummy keys, no placeholder embeddings. The product definition wins over
any stale comment.

## Stack

FastAPI + Uvicorn · Pydantic v2 models **generated** from `specs/openapi.yaml` · llama-cpp-python (GGUF, CPU) ·
ChromaDB + sentence-transformers · PostgreSQL +
SQLAlchemy 2 async + Alembic · Redis BLPOP job queue · Svelte 5 console · Docker Compose (one image for app and worker; no
service needs a GPU) · MkDocs Material docs.

## Hard constraints

1. **Wrap, never rewrite** `adapta/core/inference.py`, `adapta/core/model_manager.py`.
2. **Dependencies live in `pyproject.toml` only** and are baked into the image. Never `pip install` by hand. One
   stack: `make up` (= `docker compose up -d --build`); gates run as `docker compose exec app make <target>`.
3. **Generated artifacts are never hand-edited** — `adapta/models/generated/models.py` (`make generate`); Alembic
   migrations are autogenerated, then reviewed.
4. **No exception reaches a client as a raw string.** Raise a typed `DomainError` (`adapta/domain/errors.py`);
   `adapta/api/app.py` serializes it with a correlation ID. `make check-leaks` enforces it.
5. **Contracts change before code** (next section). Early stage, no users: fix flaws at their origin, delete
   legacy/mock code, never add a compatibility shim.

## Workflow — three contracts (Extended SDD)

| Contract | SSOT | Apply | Gate |
|---|---|---|---|
| API | `specs/openapi.yaml` | `make generate` → routers consume the generated DTOs (guard: `tests/test_generated_models_wired.py`) | `make test-contracts` (schemathesis, live server, authenticated) — green 2026-10-10: 40 operations, ~2,300 cases, 0 failures |
| DB schema | `migrations/versions/*` | `make migrate` | `make migrate-test` (up → down → up) |
| Model / eval set | `specs/schemas/eval_dataset.schema.json` (SFT row) | adapter import → registered adapter | CPU eval gate `services/eval_gate.py` (task metric, adapter vs base), run by the adapter job on every import |

Full doc: [docs/reference/SDD_WORKFLOW.md](docs/reference/SDD_WORKFLOW.md). `make ci` runs check-leaks,
check-chroma, lint, lint-imports, coverage, validate-spec and check-models; `make ci-full` adds migrate-test and
test-contracts.

```text
GET  /health · /health/deep · /gpu · /v1/models
POST /v1/auth/register · /login · /invite · /accept-invite      GET /v1/auth/me · /invitations
GET/POST /v1/projects · GET/DELETE /v1/projects/{id}             GET /v1/teams/{team_id}/members
POST/GET/DELETE /v1/projects/{id}/files                          upload (202) + queued index job on the worker
POST …/files/{fid}/extract · GET /v1/projects/{id}/fields.csv     opt-in visual extraction (vision base) + re-read of low-confidence pages
POST/GET /v1/projects/{id}/datasets · POST …/datasets/synthesize · GET …/datasets/{did}
POST/GET /v1/projects/{id}/adapters · GET/DELETE …/adapters/{aid}  GGUF or PEFT-zip import (status uploaded→…→passed)
POST/GET /v1/projects/{id}/endpoint (finetune: binds the latest passed adapter) · POST …/endpoint/promote · GET …/endpoint/history
POST/GET/DELETE /v1/projects/{id}/keys · GET …/usage
POST /v1/projects/{id}/golden · POST …/golden/run · GET …/golden/results   RAG gate: recall@5/MRR runs, regression warning
GET/PATCH /v1/settings                                           DB-backed platform overrides
POST /v1/chat/completions                                        OpenAI-compatible; adp_* key; image content-parts
```

The spec is the truth; `docs/reference/api.md` renders it.
